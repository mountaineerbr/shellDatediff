NAME

   datediff.sh - Calculate time ranges / intervals between dates

SYNOPSIS

   datediff.sh [-RRrttuvvv] [-NUM] [-f "FMT"] DATE1 DATE2 [UNIT]
   datediff.sh -FF [-v] [[DAY_IN_WEEK] [DAY_IN_MONTH]] [START_DATE]
   datediff.sh -ee [-v] YEAR …
   datediff.sh -l [-v] YEAR …
   datediff.sh -m [-v] DATE …

DESCRIPTION

Calculate the time interval (elapsed time) between DATE1 and DATE2 in various time units.

Special functions generate dates for Easter, Carnaval, and Corpus Christi, check for leap years, and generate moon phase calendars.

Input is expected as an ISO-8601 date or UNIX time. However, the script can leverage an external C-code date utility to parse a wider range of date formats.

OPTIONS

Date and Time Calculations

-[0-9], -NUM

Scale factor for single-unit float results (decimal plates).

Parameter NUM must be an integer.

-f FORMAT

Input date format specification (BSD, Toybox date).

-r, -@

Input DATES are UNIX timestamps.

-t, -tt

Table display of single-unit time intervals.

-u

Operate in UTC instead of local time.

This also affects how C-code date processes input dates.

-v

Print single-unit ranges alone (e.g. “1 day, 24 hours, 1440 mins..”).

-vv, -vvv

Print the compound range alone (e.g. “6Y 11M 01W 06D”).

Set -vvv to remove spaces (e.g. “6Y11M01W06D”), AST style.

Special Date Functions

-e [YEAR …]

Easter dates (Western Church).

-ee [YEAR …]

Carnaval, Easter and Corpus Christi dates (TSV table).

-F, -FF [[DAY_IN_WEEK] [DAY_IN_MONTH]] [START_DATE]

Next Friday the 13th or other date combinations.

Set twice to print the following ten matches.

-l [YEAR …]

Check for leap years.

Set option -v to decrease verbosity.

-m [YYYY[-MM[-DD]]]

Print moon phase for UTC DATE.

Partial DATE input is expanded automatically.

Miscellaneous

-h

Print the script help page.

-k

Suppress bold formatting (text highlighting) in output.

-R, -RR

Output dates in RFC 5322 format. Repeat the option to use names from the current time locale where supported.

-v

Decrease or change verbosity mode.

DATE AND TIME CALCULATIONS

If DATE is not given, it defaults to now. If only one DATE is set, the first date is assumed to be now (or 1970 as a last fallback).

To flag DATE as UNIX time, prepend an “at” sign (“@”) to it or set option -r.

GNU date accepts most free-form human-readable date strings. With FreeBSD and BusyBox date, the input format may be set with option -f FORMAT, such as -f "%Y-%m-%d %H:%M:%S".

Support for timezones and the %z and %Z input conversion specifiers varies between date implementations.

When no C-code date programme is available, input must be given as ISO-8601 date or UNIX time.

Standard input may contain either one DATE string per line (up to two lines), or two ISO-8601 DATES separated by a space on a single line. Input is processed on a best-effort basis.

DATE AND TIME OUTPUT

The “RANGES” output section displays intervals in different units of time (years, or months, or weeks..). It also displays a compound time range, with all units considered relative to each other.

Single-unit time periods can be displayed in table format with option -t. Set the decimal scale factor with command-line option -NUM, where NUM is an integer.

The least significant digit of the result is subject to rounding.

When the last positional parameter UNIT is exactly one of Y, MO, W, D, H, M, or S, the corresponding single-unit time interval is printed to stdout.

The “DATES” output section prints input dates as UNIX times and ISO-8601 dates, or as RFC 5322 dates if option -R is set.

If specified more than once, as in -RR, output weekday and month abbreviations from the current time locale, where supported.

Option -u sets the environment variable “$TZ=UTC” and operates internally in Coordinated Universal Time (UTC). Note that this affects how the C-code date programme processes dates.

Option -v prints single-unit ranges alone (e.g. “1 day, 24 hours, 1440 mins”). Option -vv prints the compound range alone (e.g. “6Y 11M 01W 06D”), and setting -vvv further removes spaces (e.g. “6Y11M01W06D”), AST style.

SPECIAL DATE FUNCTIONS

Option -e prints Easter dates for given YEARS (Western Church) and option -ee additionally prints Carnaval and Corpus Christi dates.

Option -l checks whether YEAR is a leap year. Set option -v to decrease verbosity and exit with a status code.

Calculations use the proleptic Gregorian calendar, include year zero, and do not account for leap seconds.

Option -m prints lunar phase for UTC DATE (“YYYY[-MM[-DD]]”). Partial input DATES are expanded automatically. Code snippet adapted from NetHack.

Option -F prints the next Friday the 13th. START_DATE must use the format “YYYY[-MM[-DD]]”. Optionally, set day-in-week and day-in-month; e.g. “Sun 01 [START_DATE]”.

Set options -FF to print the following ten matches.

TIMEZONE OFFSETS

Environment variable $TZ is read as POSIX offset. Fixed offsets do not consider daylight-saving changes.

Set $TZ using the POSIX form “UTC[+|-]HH[:MM]”, such as “UTC+03”.

Importantly, POSIX $TZ offsets use the opposite sign to ISO-8601 UTC offsets:

  • “$TZ=UTC+03” corresponds to “ISO UTC-03” (West of UTC)
  • “$TZ=UTC-03” corresponds to “ISO UTC+03” (East of UTC)

Timezone names and IDs (e.g. “America/Sao_Paulo”) may be parsed by C-code date when it is leveraged to process user input.

The $TZ variable affects the timezone offset display of output dates.

REFINEMENT RULES

Compound time range calculations follow refinement rules intended to minimise excessive granularity in the resulting units.

As of release v0.31 (Oct 2026), shell arithmetics have been fully verified against the C-code date and datediff references. No remaining divergences were found in arithmetics or refinement rules.

Most differences or errors in older releases involved month boundaries, end-of-month and start-of-month date combinations, such as days 29, 30, or 31 versus days 1, 2, or 3, unusual timezone offsets, and discrete bugs in refinement calculations.

The script’s logic strives to follow Hroptatyr’s C-code datediff refinement rules for compound ranges.

For the full testing log, check d-test.sh at the project repository.

ENVIRONMENT

DATE_CMD

Path for the C-code date command.

GNU, BSD, AST, BusyBox and Toybox date are supported.

LC_TIME

Locale for weekday and month names in RFC 5322-style output with options -RR, where supported. Nonempty LC_ALL takes precedence; LANG spplies the default.

TZ

POSIX timezone offset. The offset must be in the format “UTC[+|-]HH[:MM]”.

EXAMPLES

Leap year check

   datediff.sh -l 1900 2000 2100
   datediff.sh -l {2080..2100}

The second incantation relies on brace expansion in the invoking shell.

Moon phases for January or full year

   datediff.sh -m 2030-01
   datediff.sh -m 2030

Print the next Friday the 13th

   datediff.sh -F

Print the first Sunday falling on the 12th on or after 2030-01-01

   datediff.sh -F sun 12 2030

Single-unit time periods

   datediff.sh '10 years ago' mo #[mo]nths
   datediff.sh 1970-01-01 2000-02-02 y #[y]ears

Time ranges/intervals

   datediff.sh 0921-04-12 1999-01-31
   echo 1970-01-01 2000-02-02 | datediff.sh
   TZ=UTC+03 datediff.sh 2020-01-03T14:30:10-06 2021-12-30T21:00:10-03

GNU date warping

   datediff.sh 2019/6/28 1Aug
   datediff.sh 'next monday'
   datediff.sh '5min 34seconds'
   datediff.sh '2020-01-01 - 6months' '2020-01-01'
   datediff.sh '05 jan 2005' 'now - 43years -13 days'
   datediff.sh -2 -- '1hour ago 30min ago'
   datediff.sh -u '2023-01-14T11:20:00Z' '2023-01-14T11:20:00Z + 5 hours'
   datediff.sh -- '-2week-3day' 'now'
   datediff.sh -- 'today + 1day' @1952292365
   datediff.sh @1561243015 @1592865415

BSD date warping

   datediff.sh -f'%m/%d/%Y' '6/28/2019' '9/04/1970'
   datediff.sh -r 1561243015 1592865415
   datediff.sh 200002280910.33 0003290010.00
   datediff.sh -- '-v +2d' '-v -3w'

DEPENDENCIES

This script uses shell arithmetics for most time range calculations and relies on bc for large integers and floating-point arithmetics.

  • Bash 2.05b+, Ksh93 or Zsh 5+ is required.
  • bc Basic Calculator or Ksh93/Zsh shell is required for single-unit time calculations.
  • FreeBSD date or GNU date is optionally required to parse input dates in various formats.

DEBUGGING DEPENDENCIES

  • Sourceable helper script datediff.debug.sh.
  • C-code implementation of date.
  • C-code implementation of datediff.

DIAGNOSTICS

Option -D disables external C-code date for input date parsing.

Setting options -DD further disables time-related builtins of the shell.

Option -d executes result checks against C-code datediff and C-code date programmes in the main function (UTC time mode).

Set options -dd to exit immediately with a status number. Debug data is dumped only when checks fail.
